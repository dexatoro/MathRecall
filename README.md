# MathRecall · MVP 0.1

Локальное приложение для изучения университетской математики. Первая итерация реализует основной учебный процесс: создание материала → повторение → сохранение прогресса → резервная копия.

## Запуск на этом Mac

Откройте `start.command` двойным нажатием в Finder или выполните из папки проекта:

```sh
./start.command
```

Затем откройте **http://127.0.0.1:4173/**. Скрипт проверит TypeScript, соберёт приложение и запустит production-preview. Если системного Node нет, он использует уже установленный локальный runtime Codex. Пока папка `node_modules` сохранена, установка зависимостей повторно не нужна. Остановка сервера — `Ctrl+C` в его окне Terminal. Не запускайте одновременно два сервера на одном порту.

## Запуск на другом Mac

Нужен Node.js 24 (также совместим Node 22.12+) и pnpm 11.25.0. Для первоначальной установки зависимостей требуется интернет.

```sh
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile
pnpm dev
```

Для разработки Vite покажет адрес, обычно `http://127.0.0.1:5173/`. Для готовой сборки и офлайн-кэша:

```sh
pnpm build
pnpm preview --port 4173 --strictPort
```

Не открывайте `dist/index.html` через `file://`: IndexedDB и Service Worker требуют обычный локальный сервер или HTTPS.

## Реализовано

- React, TypeScript strict, Vite, Tailwind CSS 4 и Lucide. Русский адаптивный интерфейс, тёмная и светлая темы, доступные формы и модальные окна с управлением фокусом.
- Полный CRUD предметов, тем, вложенных подтем, билетов и карточек. Тема принадлежит предмету; билет — теме. Удаление предмета или темы удаляет вложенный материал и его историю. Удаление билета сохраняет его карточки.
- Три типа карточек: определение/теорема, доказательство, задача. Поля вопроса, ответа, подсказок и источника. Пошаговое раскрытие подсказок, live preview, защита несохранённого редактора при закрытии и перезагрузке.
- Безопасный Markdown + KaTeX. Произвольный HTML отключён, опасные ссылки отсекаются, команды KaTeX работают с `trust: false`. Внешние картинки отключены, поэтому содержимое карточки не загружает трекеры.
- Настоящий **ts-fsrs 5.4.2**: четыре оценки, прогноз интервалов, состояния New/Learning/Review/Relearning, сохранение всех полей FSRS и истории. `enable_fuzz: false` даёт воспроизводимый прогноз.
- Один общий FSRS-state карточки при связи с несколькими билетами. Карточку можно связать с несколькими билетами её темы. Новые билеты выбираются в редакторе флажками.
- Повторение всех предметов либо выбранного предмета, темы с потомками, билета. Общий дневной лимит новых карточек; повторяемые карточки лимитом не ограничены.
- Главная со списком на сегодня, поиском, фильтрами и прогрессом предметов. Статистика реальных повторений, история последних оценок, состояния и нагрузка на 7 дней.
- IndexedDB через Dexie. Состояние и история оценки сохраняются одной транзакцией. Проверка `expectedReps` и блокировка UI защищают от двойной записи, в том числе между вкладками.
- Полный JSON backup v1: предметы, темы, билеты, карточки, связи, состояния, история и настройки. Zod проверяет формат и связи. Ошибка до импорта не меняет базу; ошибка записи откатывает всю транзакцию.
- Необязательные явно помеченные демо-примеры трёх типов. Автоматически при первом запуске создаются только три пустых предмета.
- Production Service Worker сохраняет HTML, JS, CSS и все шрифты KaTeX. Основные сценарии не обращаются к API или CDN.

## Как пройти учебный сценарий

1. Откройте «Библиотека». Выберите или создайте предмет.
2. Нажмите «Тема», укажите «Последовательности». Для вложенной темы выберите родителя.
3. Создайте билет «Предел монотонной последовательности» и откройте его.
4. Нажмите «Новая карточка», заполните вопрос и ответ, проверьте предпросмотр и сохраните.
5. Откройте «Сегодня» или нажмите «Повторить» в выбранном билете.
6. Вспомните ответ, раскройте подсказки при необходимости, нажмите «Показать ответ» или Space.
7. Выберите «Снова», «Трудно», «Хорошо» или «Легко» кнопкой или клавишей 1–4. До раскрытия ответа оценка недоступна.
8. Следующая дата видна на экране завершения и в деталях карточки. Перезагрузка сохраняет весь прогресс.
9. В настройках скачайте JSON. Для восстановления выберите файл и подтвердите замену библиотеки.

Формулы в строке: `$a_n \to a$`. Блочные формулы: `$$` на отдельной строке до и после формулы. Подсказки в редакторе разделяются пустой строкой.

## Как устроена очередь

«На сегодня» включает новые, просроченные и запланированные до конца текущих локальных суток карточки. Кнопка повторения берёт только карточки, чей срок уже наступил, с учётом дневного лимита. Поэтому число в плане может быть больше числа доступных повторений.

Сессия фиксирует список доступных карточек при старте. После оценки карточка покидает эту сессию. Если FSRS назначил следующий шаг через 1–10 минут, карточка снова станет доступна на главной в свой срок. Сессия не ускоряет время FSRS. Завершение или закрытие сессии не отменяет уже сохранённые оценки.

Даты в IndexedDB — `Date`; в JSON — ISO 8601 UTC; отображение и границы дня используют локальную временную зону браузера.

## Офлайн и надёжность хранения

Для офлайн-перезагрузки один раз откройте production-сборку с работающим сервером и дождитесь в настройках статуса «Готово к работе без сети». Кэш отключён в dev-режиме. Требуется поддержка Service Worker и безопасный контекст (localhost/127.0.0.1 или HTTPS). После обновления сборки закройте старые вкладки приложения и откройте его заново для активации новой версии кэша.

Локальные данные принадлежат **конкретному браузеру и origin**. `localhost:5173`, `127.0.0.1:4173` и опубликованный домен имеют разные базы. Переносите данные через JSON. Приватный режим и очистка данных браузера могут удалить библиотеку. Сохраняйте резервные копии.

## Архитектура

- `src/model.ts` — Zod-схемы и типы основных сущностей, UUID и временные метки.
- `src/db.ts` — нормализованные таблицы Subject, Topic, Ticket, Card, TicketCard, ReviewState, ReviewLog и Settings. Dexie schema v1 — исходная версия для будущих миграций.
- `src/services/repository.ts` — CRUD, проверки отношений, каскадное удаление, выборка очереди и атомарная запись оценки.
- `src/services/scheduler.ts` — адаптер ts-fsrs, прогноз и границы дня.
- `src/services/backup.ts` — экспорт, валидация, атомарное восстановление и скачивание JSON.
- `src/components/` — навигация, редакторы, просмотр Markdown, повторение, настройки и статистика. `App.tsx` координирует экраны, фильтры и диалоги. `ui.ts` содержит общие названия экранов; полный перевод интерфейса остаётся отдельной задачей.
- `vite.config.ts` — production-прекэш всех ресурсов. Сопоставление локальных статических файлов игнорирует `Vary: Origin`, чтобы module scripts находились в кэше при офлайн-загрузке.

Для этой итерации источник — текстовое поле карточки. Таблицы Source, ImportBatch, CardDraft и миграции для них добавятся вместе с импортом конспектов, без пустых экранов и фиктивных обработчиков.

## Ограничения и следующая итерация

По согласованному приоритету отсутствуют ИИ-генерация, PDF-импорт, авторизация и синхронизация. Также отложены импорт текста/конспектов и очередь черновиков, отдельная модель источников и их страниц, полный английский перевод и оптимизация параметров FSRS по истории. Нет изображений в карточках, OCR, undo оценки, фоновых уведомлений и слияния резервных копий: импорт заменяет всю библиотеку после подтверждения. Связь с билетом сейчас ограничена темой карточки. Фильтр темы включает её потомков; фильтр билета всегда использует общий прогресс.

На следующем этапе можно добавить импорт текста и PDF с подтверждением черновиков, затем адаптер генератора. Авторизация и облачная синхронизация потребуют отдельного серверного решения и разрешения конфликтов.

## Будущее развёртывание

Приложению достаточно статического HTTPS-хостинга:

```sh
pnpm install --frozen-lockfile
pnpm test
pnpm build
```

Разместите **всё содержимое `dist/`** вместе со `sw.js` на хостинге. Можно размещать в подпапке: сборка использует относительные пути. Для `index.html` и `sw.js` задайте `Cache-Control: no-cache`; хешированные `assets/` можно кэшировать надолго. Сервер, аккаунты и API-ключи не нужны. Реальная публикация в этой итерации не выполнялась.
