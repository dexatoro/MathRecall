# MathRecall · обмен карточками v1

Формат для внешнего ChatGPT или другого генератора и ручного обмена карточками. Импорт работает локально, без API-ключей, платных запросов и авторизации.

## Два разных JSON-формата

| Назначение | `format` | `version` | Что происходит |
| --- | --- | --- | --- |
| Обмен учебными карточками | `MathRecall.CardExchange` | `1` | Добавляются черновики. Библиотека меняется только после принятия. |
| Полная резервная копия библиотеки | `MathRecall` | `1` | Восстанавливаются ID, библиотека, настройки, FSRS и история. Доступно в настройках. |

Формат резервной копии не менялся. В него не входят черновики и журнал импортов. Они хранятся отдельно в IndexedDB и сохраняются при восстановлении библиотеки; «Удалить всё» в настройках удаляет и их.

## Файлы формата

- JSON Schema: `public/formats/mathrecall-card-exchange.v1.schema.json` (Draft 2020-12).
- Пример со всеми тремя типами: `public/formats/mathrecall-card-exchange.v1.example.json`.
- Источник схемы: `src/import/schema.ts`. Схема для публикации создаётся из Zod, а не поддерживается вручную отдельно.
- Обновление файлов: `pnpm generate:exchange`. Генератор использует встроенную поддержку TypeScript в Node с `--experimental-strip-types`.
- Тест сверяет опубликованные Schema и пример с текущими Zod-схемами и образцом.

## Структура

```json
{
  "format": "MathRecall.CardExchange",
  "version": 1,
  "cards": [
    {
      "type": "definition",
      "subject": "Математический анализ",
      "topicPath": ["Последовательности"],
      "tickets": [
        { "name": "Предел последовательности", "description": "" }
      ],
      "question": "Что означает $a_n \\to a$?",
      "answer": "Для каждого $\\varepsilon>0$ существует $N$, такое что при $n\\ge N$ выполняется $|a_n-a|<\\varepsilon$.",
      "hints": ["Начните с квантора «для каждого»."],
      "sources": [
        {
          "title": "Мой конспект",
          "url": null,
          "pageStart": 12,
          "pageEnd": 13
        }
      ]
    }
  ]
}
```

Все поля обязательны. Неизвестные поля запрещены. Обязательные поля без значений задаются через `[]`, `null` или `""`, как описано ниже. Не включайте ID, FSRS-state, оценки и историю.

| Поле карточки | Значение |
| --- | --- |
| `type` | `definition`, `proof` или `problem`. Теоремы и свойства без отдельного доказательства относятся к `definition`. |
| `subject` | Непустое название предмета, максимум 200 символов. |
| `topicPath` | От 0 до 12 названий тем от корня к последнему уровню. `[]` — без темы. Каждое название — до 200 символов. |
| `tickets` | От 0 до 30 объектов `name`/`description`. Все относятся к последней теме. Если тем нет, билетов быть не должно. Название непустое, до 200 символов; описание может быть пустым, до 20 000. |
| `question`, `answer` | Непустой Markdown с LaTeX, до 20 000 символов каждый. |
| `hints` | До 100 непустых подсказок, каждая до 20 000 символов. `[]` — без подсказок. |
| `sources` | До 10 источников. `[]` — источник неизвестен. |

Источник содержит `title` (непустое название до 200 символов), `url` (ссылка http/https до 1000 символов либо `null`), `pageStart` и `pageEnd` (целые от 1 до 100 000 либо `null`). Номера страниц считаются с 1. Если указан `pageEnd`, нужен `pageStart`, причём `pageEnd >= pageStart`. Для одной страницы можно указать только `pageStart`, а `pageEnd: null`.

Если есть URL и начальная страница, ссылка в предпросмотре, библиотеке и повторении получает фрагмент `#page=N`. Диапазон страниц отображается в подписи. Это переход к странице в поддерживающем такую навигацию просмотрщике PDF; файлы приложение не скачивает и не анализирует. Без URL сохраняются название и страницы как текст. Итоговое представление источников ограничено 2000 символами для совместимости с прежним `Card.source`.

Связанные проверки страниц, наличия темы для билетов и длины итогового представления источников выполняет Zod дополнительно к структурной JSON Schema. Названия и содержимое обрезаются по краям от пробельных символов; пробельные названия и ответы не принимаются.

## LaTeX в JSON

Обратную косую черту нужно экранировать: LaTeX `\varepsilon` записывается внутри JSON-строки как `\\varepsilon`. После разбора JSON исходные LaTeX-команды сохраняются в черновике и карточке. Никакие формулы не извлекаются эвристически и не переписываются.

Формула в строке: `$a_n \\to a$` в JSON. Для блочной формулы ставьте `$$` на отдельных строках, например JSON-строка `"Решение:\n\n$$\n2^n\n$$"`.

В интерфейсе используется прежний безопасный Markdown/KaTeX: HTML не исполняется, внешние картинки отключены, небезопасные ссылки отсекаются.

## Рабочий процесс

1. Откройте «Импорт карточек».
2. Нажмите «Скопировать промпт для ChatGPT». В инструкции уже есть точные Schema, пример и правила экранирования. Вставьте её во внешний ChatGPT, затем отправьте свой материал. Приложение не передаёт данные в ChatGPT самостоятельно.
3. Если автоматическое копирование недоступно, нажмите «Открыть промпт» и скопируйте текст вручную.
4. Загрузите JSON-файл или вставьте JSON в поле. Для вставки доступны кнопка чтения буфера и обычные ⌘V / Ctrl+V. Ограничения: 2 МБ, 1–500 карточек. Одно внешнее ограждение ```json тоже принимается; JSON внутри должен быть валиден.
5. После успешной проверки все карточки попадут в постоянную очередь черновиков. Невалидный пакет не создаёт частичных записей. Ошибки содержат точный путь, например `cards[0].answer`.
6. В «Просмотре» проверьте формулы, подсказки, билеты и источники. Редактор позволяет изменить все поля, включая путь темы, несколько билетов и страницы источников. Сохранение редактора не принимает карточку в обучение.
7. Отклоните ненужные черновики, примите отдельные, выбранные флажками или все ожидающие в текущем фильтре. Отклонённые можно вернуть. Фильтры пакета и статуса ограничивают массовые действия.
8. Только при принятии создаются отсутствующие предметы, вложенные темы, билеты, карточки и связи. Каждая новая карточка получает один новый FSRS-state через прежний адаптер `newState`; история остаётся пустой до первой оценки.
9. Откройте созданный предмет или билет в библиотеке и начните повторение.

Очередь и история решений сохраняются после перезагрузки. Повторные клики и параллельное принятие защищены транзакциями. При ошибке записи откатывается всё принятие выбранных черновиков, включая предметы, темы и билеты. Конфликтующее редактирование черновика выявляется через номер ревизии.

## Объединение и дубликаты

Названия предметов, тем и билетов сравниваются после Unicode-нормализации, удаления лишних пробелов и приведения регистра. Темы дополнительно различаются по предмету и родителю, билеты — по теме. Уже существующие описания не переписываются.

Карточка считается очевидным дубликатом, если совпадают нормализованные предмет, полный путь темы, тип, вопрос и ответ. В вопросе/ответе нормализуются Unicode и пробелы, но **регистр сохраняется**: `$A$` и `$a$` — разные обозначения. Разные ответы и разные пути тем остаются самостоятельными карточками. Семантического или нечёткого поиска дубликатов нет.

Дубликаты тоже сначала попадают в черновики с предупреждением. При принятии дубликата новая карточка не создаётся: добавляются только отсутствующие связи с билетами. Текст, подсказки, источники, все поля FSRS, даты и история существующей карточки не изменяются. Изменённые подсказки или источники дубликата не перезаписывают оригинал — для их изменения откройте карточку в библиотеке. Между дубликатами в одном пакете сохраняется первая принятая версия; её можно выбрать явно одиночным принятием.

Если в старой библиотеке уже есть одноимённые предметы, импорт по возможности использует существующую карточку и её фактическую тему. При создании нового материала среди одноимённых предметов выбирается тот, у которого уже существует самый длинный начальный путь тем; при равенстве — наиболее ранний. Среди одноимённых тем и билетов внутри одного родителя выбирается наиболее ранняя сущность. Разрешение смысловой неоднозначности названий вручную остаётся ответственностью пользователя при проверке черновика.

## Хранение и совместимость

Dexie v2 добавляет только `cardDrafts` и `importBatches`; старые таблицы, UUID и модель FSRS не меняются. Принимаемые ссылки на источники преобразуются в безопасный Markdown прежнего `Card.source`, поэтому экспорт и восстановление backup v1 сохраняют их без нового формата. Принятые черновики остаются журналом обработки; удаление карточки из библиотеки или восстановление другой копии не принимает их повторно.

Платные API, PDF-извлечение, ИИ-адаптер и авторизация не добавлены. Генерацию выполняет выбранный пользователем внешний инструмент; до подтверждения импорта ничто не попадает в расписание.
